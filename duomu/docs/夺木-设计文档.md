# 《夺木》设计文档

日期：2026-11-13　状态：v1 可玩版

## 1. 一句话

在通天建木下，和另一个仙人抢同一节木段——雷印蒙着的那半秒里出手能拿三分，但劈错边就当场化灰。

## 2. 参考与差异化

参考品类：反应类街机（TimberGuy / Timberman）。只借用「竖向木段 + 左右躲避」的骨架，其余全部重做。

三条「不是换皮」的理由：

1. **把随机数换成对手。** 原版是「你和随机数赛跑」，单人三分钟就腻；本作两个玩家共享同一棵树、同一批雷印，输赢来自对手的压力。
2. **把躲避换成下注。** 原版只有一个动词（点左右），且永远有唯一正解；本作每一节都是一次「早出手 / 晚出手」的下注，风险与收益显式挂钩。
3. **把「活更久」换成「抢更多」。** 目标从无限续命改成先夺 26 木，一局 15–25 秒，适合来回打十局。

## 3. 签名记忆点

**「蒙着的那半秒，你敢不敢先砍。」** 玩家第二天会跟朋友描述的就是这个瞬间：雷印还没亮，你赌了一把，屏幕炸成金色的三分。

## 4. 核心循环

```
落下一节木段
   ↓
0–450ms  蒙面   → 出手 = ×3（赌）
450–900ms 微光  → 出手 = ×2（七成准）
900ms+   明牌   → 出手 = ×1（稳）
   ↓
同一节第一个出手的人 +1（先手）
   ↓
劈中雷印 → 扣血 + 硬直
计时走完没出手 → 天雷只劈你
双雷段 → 谁碰谁死，只能等
   ↓
先到 26 木 / 劈光对面血 → 结算
```

## 5. 为什么是「先手 +1」而不是「赢者通吃」

第一版设计是「一节只能被一个人砍走」。自对弈立刻暴露问题：**手快的人会把分全吃光**，
单人模式下变成「要么必胜要么必输」——AI 反应 300ms 时人类胜率 96%，因为每一节都被人类先砍到。

改成「两边各砍一刀、先手 +1」之后：

- 速度仍然值钱（先手分 + 更早的时间窗）
- 但不会一家吃光，落后方永远有翻盘空间
- 单人胜率曲线变成 100% / 64% / 50%

这条是自对弈工具直接抓出来的，不是拍脑袋。

## 6. 数值

| 项 | 值 | 理由 |
| --- | --- | --- |
| 初始血 | 3 | 容许两次失误，第三次出局 |
| 目标木数 | 26 | 一局 15–25 秒 |
| 硬直 | 620ms | 够对手白拿一节，但不至于连坐 |
| 微光准确率 | 70% | 值得赌，但不能闭眼赌 |
| 双雷段停留 | 1000 / 950 / 880ms | 第二劫引入，作为「只能等」的呼吸点 |
| 三劫窗口 | 450 / 380 / 300ms | 每劫收紧约 15%，不是单纯加数值 |

三劫各引入一条**新规则**，不是数值膨胀：风=单侧印，火=双雷段，雷=窗口收紧 + 双雷概率上升。

## 7. 反范围（这一版明确不做）

1. 不做联网对战（只做同屏双人 + 单人对 AI）
2. 不做角色养成 / 解锁树
3. 不做关卡编辑器和每日挑战
4. 不做排行榜服务器（只有本地最高夺木）
5. 不做小程序 / 原生包

## 8. AI 设计原则

**电脑不作弊。** 它在雷印亮起前同样不知道答案，只有三个参数不同：

- `reactMs`：反应时间（430 / 300 / 170）
- `aggr`：抢跑与赌微光的倾向（0.06 / 0.36 / 0.66）
- `mistake`：手抖劈错边（0.14 / 0.06 / 0.02）

玩家输了要怪自己手慢，不能怪系统偷看。

## 9. 美术方向

需求是「对抗感必须一眼读出来」，所以：

- **两套主色贯穿全局**：赤（`#e2432e`）与青（`#3fb6d8`），HUD、角色、光效、按钮全部只用这两色区分敌我
- **树是战场**：通天建木从画面顶部贯穿到底，占据 46% 宽度，是唯一的视觉主体
- **只有最下面一节有锯切面**：上面是一条不断的树干，避免「一摞树桩」的廉价感
- **雷印是暖色裂痕**：黑底加色混合，在全暗的树皮上直接发光
- **UI 用玉牌 + 金框**，与游戏的东方神话调性一致

## 10. 技术约束

- 零构建纯静态，ES Module，无 npm / CDN
- 固定 60Hz 逻辑步长（掉帧不改判定）
- 逻辑层纯函数化，可在 Node 里无头跑完整对局
- 画布 720×1280 竖版，letterbox 适配任意视口
- 所有可调参数集中在 `config/game.config.js`
