## 素材逆向与高清化（2026-11 新增）

### 1. 从 ROM 解 CHR

```bash
python3 tools/extract_chr.py
```

- 解析 iNES 头，取 32 个 CHR bank（512 图块/bank，共 **16384 个 8×8 图块**）
- 输出 `assets/extracted/chr/bank-XX.png` 与 4 bank 一张的 `contact-XX.png`
- 图块按 NES 2bpp 解码，保留 0–3 色阶，可继续做拼图/字库/调色板分析

### 2. 从运行中的原版截帧

```bash
# 需要先起 srw2-web 的服务（127.0.0.1:8123）
python3 tools/extract_scene.py
```

- 用 Playwright 驱动 FCEUmm 核心，模拟 START/A 键穿过标题与开场对话，进入第 1 话战场
- 用 `gameManager.screenshot()` 取 **256×224 原生帧**（不是拉伸后的画布）
- 裁出：3 张 NPC 立绘（乔 / 由美 / 大卫，38×42）、第 1 话全图（256×184）、6 种地形图块（16×16）

### 3. 阿里云高清化（qwen-image-3.0 图生图）

```bash
python3 tools/hd_upscale.py \
  --input assets/extracted/scene/scenario01-map@3x.png \
  --prompt "把这张 FC 战场地图重绘为高清战棋场景，保持地形布局与配色…" \
  --size 1024*768 --output assets/hd/scene-01-map.png
```

- 地图：`assets/hd/scene-01-map.png`（1024×768），保留草原格 / 橙色岩山 / 要塞砖墙 / 海面布局
- 立绘：`assets/hd/portrait-{jo,yumi,dawei}.png`（1024×1024，赛璐璐上色）
- **踩坑**：`qwen-image-edit` 模型不存在；`wanx2.1-imageedit` 的 super_resolution 要求公网 URL，data URI 被拒，DashScope OSS 直传返回 403；最终用 `qwen-image-3.0` 的 image+text 输入做「重绘式高清化」
- **审核**：红发女性角色连续两次被 `IPInfringementSuspect` 拒绝，改成「原创驾驶员 + 只参考配色构图」的描述后通过。角色越像原作，越容易被拦

### 4. 音乐提取

- 在页面里 hook `AudioContext`，把主输出 tee 到 `MediaStreamDestination`，用 `MediaRecorder` 录下 21.9 秒战场 BGM
- `ffmpeg` 淡入淡出 + loudnorm 归一化 → `assets/audio/bgm-sortie.mp3`
- 游戏内 `<audio loop>` 播放，HUD 的 ♪ 可开关

- 战场 BGM = 从原版录制的音轨循环

### 12. 地图尺寸错误与正确数据源（2026-11-08 核实）

**用户指出的是对的**：第 1 话的地图不是 16×11。

- 我们之前只截了一屏（16×11），SRW2 的战场比一屏大，镜头会跟随光标滚动
- 核实来源：[GCGX 第1话解析](https://gcgx.games/srw2/map/01.html) 给出完整坐标：
  - 我方：高达 (12,16)、阿芙罗迪 (14,16)、魔神Z (13,17)、盖塔1 (12,18)、德州麦克 (14,18)、白色要塞 (15,19)
  - 敌方：扎古 (3,10)(4,10)(5,10)(8,3)(9,4)(10,5)(9,2)(10,3)(11,4)、达布拉斯M2 (7,6)、加拉达K7 (8,7)、宰恩Ⅱ (12,1)、兹萨 (11,3)
  - 增援（11EP）：夏亚 (1,0)、德尼姆 (2,0)、金 (2,1)
- 对应地图是 **17×21 格**（官方全图 273×337，含 1px 边框；`assets/extracted/maps/official-01.png`）

**结论**：现有 16×11 的「地图」只是原版左上角的一屏，所以地形和站位必然不对。
正确做法需要两步改造：

1. **地图改为 17×21（按话数不同）**，画布引入镜头偏移与滚动（跟随光标/选中单位）
2. **站位与地形按 GCGX 逐话坐标表**录入（26 话都有，链接见上）

这两步不是数据微调，涉及引擎坐标与渲染相机，属于下一阶段的结构性改动；在完成前，
当前版本的地图仍应视为「示意地形」，不能当作原版还原。

## v3.4（2026-11-10）：前摇 / 蓄力 / 闪避 / 受击

## v3.9（2026-11-11）：骨骼动画 + 状态机 + 武器挂载 + 动画事件

战斗 cut-in 从「整身图片 + 独立特效」升级成一套真正的层级动画系统（混合方案）：

- **骨骼层级**：`root → torso → shoulder → upperArm → forearm → hand → weaponSocket → muzzle`。
  身体立绘挂在 root/torso 骨骼上，手臂、武器、枪口是独立骨骼；支持层级世界变换。
- **武器挂载**：`weaponSocket` 在手掌骨骼上，武器角度/枪口由 socket 和 muzzle 骨骼决定；
  光束、炮弹、斩击都从挂载后的枪口/刀尖发出。
- **动画状态机**：`idle → windup → attack → recover`，由统一的归一化时间驱动；
  `fire / impact` 作为动画事件触发伤害数字、闪避、受击和特效，避免帧率影响判定。
- **不同武器姿势**：步枪/机枪/加农炮/火箭筒/光束军刀/斧/拳/火焰/地图兵器/光弹分别定义
  武器长度、握持角度、手臂姿态和特效类型；同一套骨骼复用。
- **混合式**：身体主体保持现有侧面立绘（刚性 body 骨骼），手臂和武器用程序化骨骼，
  枪口火焰/光束/爆炸用 Canvas 特效，符合「不要把所有动作都做成骨骼」的实用方案。
- 验收 78 项，新增「骨骼/武器 socket 跟随手部」「动画状态机/事件顺序」；
  截图 `docs/screenshots/19-skeletal-windup.webp`、`20-skeletal-saber.webp`、`21-skeletal-impact.webp`。
